# Force-dynamic list page, Server Actions + revalidatePath, raw SQL

`next.config.ts` does not enable Cache Components (`cacheComponents: true`), so the app runs under Next.js's previous caching model, where a plain `@neondatabase/serverless` query is not auto-detected as a dynamic API the way `cookies()`/`headers()` are. Without an explicit opt-out, the entry list risks being statically cached and served stale after a mutation. The list page therefore sets `export const dynamic = 'force-dynamic'`. Create/edit/delete are Server Actions (not Route Handlers, not client-side `fetch`) that call `revalidatePath('/')` on success, matching the single-page, no-login shape of the app. Persistence is raw parameterized SQL via `@neondatabase/serverless`, no ORM — consistent with the brief's explicit "no ORM" instruction and the small, fixed schema.
