# Verify entry passwords with node:crypto scrypt, not a hashing library

Each entry's password must be checked on edit/delete without ever storing or returning the raw value. We derive a per-entry random salt and a scrypt hash via Node's built-in `node:crypto` (`scrypt`), storing them as a single `salt:hash` hex column, instead of adding `bcrypt`/`argon2` as a dependency. This avoids native-module install risk under exam time pressure and works on Vercel's Node.js serverless runtime; it requires Server Actions and any route touching passwords to run on the Node runtime, not Edge, since Edge has no `node:crypto`. Entries are addressed by an ordinary `BIGSERIAL id` exposed to the client — it is not treated as a secret, since the password (not the id) is the actual access control.
